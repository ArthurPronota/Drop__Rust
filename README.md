# Описание `Drop` в Rust

## Что такое `Drop`

**`Drop`** — трейт из стандартной библиотеки с **одним** методом:

```rust
pub trait Drop {
    fn drop(&mut self);
}
```

**Что делает:** **освобождает ресурсы** при **уничтожении** значения.

## Что освобождает `Drop`

| Ресурс | Пример |
|---|---|
| **Память** | `String`, `Vec`, `Box` |
| **Файлы** | `File` |
| **Соединения** | `TcpStream` |
| **Блокировки** | `MutexGuard`, `RwLockGuard` |
| **Сокеты** | `TcpListener` |
| **Дескрипторы** | `File`, `EventFd` |

## Когда вызывается

**Автоматически** компилятором в **точке выхода** значения из **области владения**.

### Вызывается при

- **нормальном** завершении (выход из `{}`);
- **переприсваивании** (для старого значения);
- **`std::mem::drop(x)`**;
- **unwinding-панике** (если `panic=unwind`).

### НЕ вызывается при

- **`std::mem::forget(x)`** — функция **не** вызывает деструктор;
- **`abort`** процесса (`panic=abort` или `std::process::abort`);
- **`std::process::exit`**;
- **`ManuallyDrop`**;
- **`Box::leak`**;
- **циклах `Rc`/`Arc`**.

## Разбор вашего примера

```rust
struct Guard;

impl Drop for Guard {
    fn drop(&mut self) {
        println!("Drop data!");
    }
}

fn main() {
    let g = Guard;

    drop(g);   // ← явный вызов std::mem::drop
}
```

**Вывод:**

```
Drop data!
```

### Что происходит

1. **`Guard`** реализует `Drop`.
2. **`g = Guard`** — создан.
3. **`drop(g)`** — **`std::mem::drop`** **забирает** владение.
4. **В конце `drop`** — `g` **уничтожается** → вызывается `Drop::drop`.
5. **Вывод:** `"Drop data!"`.

## Почему **нельзя** вызвать `drop()` вручную

```rust
let mut g = Guard;
g.drop();   // ❌ E0040
```

**Ошибка:**

```
error[E0040]: explicit use of destructor method
```

**Причина:** если бы это **разрешили**, компилятор **всё равно** вставил бы **свой** вызов `drop` при выходе → **двойное** освобождение → **UB**.

## `std::mem::drop` — правильный способ

```rust
pub fn drop<T>(_x: T) { }
```

**Что делает:**

- **Принимает** `x` **по move**.
- **Ничего** не делает в теле.
- **В конце** `drop` (функции) **вызывается** деструктор `x`.

**Это просто** **пустая** функция, которая **забирает** владение.

### Пример

```rust
let g = Guard;
drop(g);   // ← std::mem::drop

// g больше недоступен — владение перемещено
```

## `Drop` и `Copy` — **взаимоисключающие**

```rust
#[derive(Copy, Clone)]
struct Guard;

impl Drop for Guard { ... }   // ❌ E0040
```

**Ошибка:**

```
error[E0184]: the trait `Copy` cannot be implemented for this type;
              the type has a destructor
```

**Причина:** `Copy` **дублирует** значение → **два** `drop` на **одну** память → **двойное** освобождение.

## Порядок `Drop`

| Что | Порядок |
|---|---|
| **Поля структуры** | В порядке **объявления** |
| **Локальные переменные** | В **обратном** порядке создания (LIFO) |

### Пример

```rust
struct Pair {
    a: A,
    b: B,
}

// drop(a), потом drop(b)
```

### Пример с локальными

```rust
fn main() {
    let _a = A;
    let _b = B;
    let _c = C;
}
// drop(c), drop(b), drop(a)
```

## `Drop` и RAII

**RAII** (Resource Acquisition Is Initialization) — **главная** цель `Drop`:

```rust
{
    let guard = mutex.lock().unwrap();
    // критическая секция
}   // ← drop(guard) автоматически разблокирует
```

**Гарантия:** ресурс **освободится**, даже при **панике**.

## `Drop` при панике

**Unwinding** (раскрутка стека) — механизм Rust по умолчанию при `panic!`. При **раскрутке** вызываются **все** `Drop` для **живых** значений.

```rust
fn main() {
    let _g = Guard;
    panic!("oops");   // ← drop(_g) всё равно вызовется
}
```

**Вывод:**

```
Drop data!
thread 'main' panicked at 'oops'
```

## Нельзя **паниковать** в `Drop::drop`

```rust
impl Drop for Guard {
    fn drop(&mut self) {
        panic!("oops");   // ⚠️ опасно
    }
}
```

**Проблема:**

- Если **уже** идёт **паника** → **double panic** → **`abort`**.
- Программа **аварийно** завершится.

**Правило:** в `Drop::drop`:

- **не** вызывать `.unwrap()`;
- **не** делать **потенциально** падающих **операций**;
- **логировать** ошибки, но **не** паниковать.

## `Drop` и **move**

```rust
let a = Guard;
let b = a;   // ← move: владелец теперь b
// drop(a) НЕ вызывается
// drop(b) при выходе
```

**`Drop`** вызывается **один раз** — для **последнего** владельца.

## `std::mem::forget`

```rust
let g = Guard;
std::mem::forget(g);   // ← drop(g) НЕ вызовется
```

**Применение:** **намеренно** не освобождать (редко, осторожно).

## Итог

- **`Drop`** — трейт с `fn drop(&mut self)`.
- **Освобождает:** память, файлы, соединения, блокировки, сокеты, дескрипторы.
- **Вызывается** **автоматически** в точке выхода.
- **Не вызывается** при `mem::forget`, `abort`, `process::exit`, `ManuallyDrop`, `Box::leak`, циклах `Rc`.
- **Руками** `drop()` **нельзя** — **E0040**.
- **Правильно** — `std::mem::drop(x)` (забирает владение).
- **`Drop`** **несовместим** с **`Copy`**.
- **Порядок:** поля — в **порядке** объявления; локальные — **LIFO**.
- **RAII** — **главная** цель.
- **Паника** в `Drop::drop` **опасна** (double panic → abort).
- **В вашем примере:** `drop(g)` → `"Drop data!"`.
- **Правило:** `Drop` — **автоматическое** освобождение; **руками** — только `std::mem::drop`.
